# ADR-038: ADR 確定前検証（Spike）パターンの導入

## ステータス

採用済み

## 関連 ADR

- 依存: [ADR-025](025-adr-reference-skill.md)（ADR 運用ルール・ステータス定義の基盤）

## コンテキスト

ADR 駆動開発では「ADR 議論決着 → `adr-ship` で実装」のサイクルを前提としているが、設計を確定させるために実際に作って検証しないと判断できないケースがある。

例：
- データソース間のタイムスタンプ対応付けが技術的に実現可能か（ADR-037）
- 未知のコンポーネント間の相互作用の挙動確認

現状の運用ではこのケースに対して以下の問題がある：

1. Draft ADR のまま「なんとなく実装」が始まり、意思決定の記録が後追いになる
2. 検証用コードが main ブランチに混入するリスクがある
3. 検証中の ADR が通常の Draft と区別できず、`adr-ship` で誤って実装フローに入ることがある

このケースはエッジケースであり、仕組みの大幅な変更ではなく最小限の規約追加で対応する。

## 設計案

### 案A: `Spike中` ステータス追加 + Spike ブランチ規約（採用）

ADR-025 のステータス定義に `Spike中` を追加し、`development.md` に Spike フローを記述する。

**フロー**:

```
create-spec（受け入れ条件に「Spike: 〜を検証する」を明記）
→ ADR ステータスを "Spike中" に設定
→ spike/NNN-description ブランチで検証実装
→ 検証結果を ADR の コンテキスト or 設計案 セクションに追記
→ ADR ステータスを Draft に戻し、設計を確定
→ adr-ship で正式実装（通常フローに合流）
```

**規約**:
- Spike ブランチ名: `spike/NNN-description`（NNN = ADR 番号）
- Spike コードは main にマージしない（検証完了後は捨てる）
- `adr-ship` は `Spike中` ステータスの ADR には適用しない

### 案B: issues.md に「検証フェーズ」セクション追加（却下）

受け入れ条件の前に検証タスクを書くフォーマットを追加する。

- 却下理由: ADR のステータスで状態を識別できないため、Spike 中の ADR を誤って `adr-ship` で扱うリスクが残る。また issues.md のフォーマットが複雑化する

### 案C: ブランチ規約のみ追記（却下）

`development.md` に1行追記するだけで、ADR ステータスは変えない。

- 却下理由: 検証中の ADR が通常の Draft と区別できないため、状態が外から判別不能

### 変更が必要なファイル

| ファイル | リポジトリ | 変更内容 |
|---|---|---|
| `.claude/skills/adr-reference/skill.md` | dotfiles | `Spike中` ステータスの追加、遷移ルールの追記 |
| `docs/development.md` | dotfiles | Spike パターンのフロー記述を追加 |
