# 実装スコープ

- 明示された要求を満たす最小の一貫した変更を行う。
- 新しい抽象化・ヘルパー・依存・設定オプション・retry・fallback・永続化機構・
  互換レイヤーは、明示された要求、再現済みのバグ、既存のリポジトリ不変条件の
  いずれかに紐づかない限り追加しない。
- 推測に基づく将来要件を実装しない。タスクと無関係なコードのリファクタ・
  リネーム・「改善」をしない。
- このタスク中に自分が作ったコード・テスト・ドキュメントを、さらに機構を
  追加する根拠として扱わない。
- 新しい依存、公開 API、スキーマ migration、設定オプション、永続状態、
  バックグラウンドプロセス、リポジトリ全体のリファクタリングを導入する前に、
  実装せず停止して提案する。

# コメント

- コメントは将来のコードの読み手に向けて書く。この diff のレビュアーに向けて
  書かない。変更自体の説明はコードではなく PR description に書く。
- コメントが正当化されるのは、コードで表現できない事柄のみ: 自明でない
  不変条件、workaround とその外部要因、本当に必要な警告。
- 手順のナレーション、セクション見出しコメント、changelog 風コメント
  (「X を追加」「ここで〜する」)、シグネチャをなぞるだけの docstring を
  書かない。
- 周辺コードのコメント密度に合わせる。

# ドキュメント

- 明示的に依頼されない限り、新しいドキュメントファイルを作らない。
- 既存ドキュメントは、今回の変更によって事実と食い違う場合のみ更新する。
  判定基準: 「これを書かないと将来の開発者が実質的に誤った判断をするか？」
  No なら書かない。

# 最終化の前に

- 最終 diff を 1 回だけ見直し、上記ルールに反するコメント・ドキュメントと、
  どの要求にも紐づかない変更を削除する。このパスでは何も追加せず、
  さらなる改善も行わない。
