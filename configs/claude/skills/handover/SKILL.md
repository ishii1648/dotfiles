# セッション引き継ぎ（Handover）

## 概要

セッション終了時に作業内容・設計判断・次のアクションを構造化して `HANDOVER.md` に記録するスキル。Claude Code の auto compact はセッション内のコンテキストウィンドウ管理のみを行い、セッション間の文脈は保持しない。本スキルはその欠点を補い、セッション跨ぎでの作業継続性を確保する。

## ワークフロー

### Step 1: 現在の作業状態を収集

以下の情報を並列で収集する：

```bash
# 現在のブランチ
git branch --show-current

# 最近のコミット履歴（当日分）
git log --oneline --since="midnight" --no-merges

# 未コミットの変更
git status --short

# ステージング済みと未ステージングの差分サマリー
git diff --stat
git diff --cached --stat
```

### Step 2: セッションコンテキストの整理

会話のコンテキストから以下の情報を構造化する：

1. **今回やったこと**: 実施した作業の箇条書き
2. **決定事項**: 設計上・実装上の決定とその理由
3. **捨てた選択肢と理由**: 検討したが採用しなかった案
4. **ハマりどころ**: 遭遇した問題とその解決策
5. **学び**: 発見した知見やパターン
6. **次にやること**: 未完了のタスクや次ステップ
7. **関連ファイル**: 作業に関連する主要ファイル一覧

### Step 3: HANDOVER.md の生成

プロジェクトルート（`$PWD`）に `HANDOVER.md` を生成する。

既存の `HANDOVER.md` がある場合は**上書き**する（過去の引き継ぎは git 履歴で参照可能）。

#### 出力フォーマット

```markdown
# Handover Note

> Generated: YYYY-MM-DD HH:MM
> Branch: <current-branch>
> Trigger: manual

## 今回やったこと

- [作業内容1]
- [作業内容2]

## 決定事項

- **[決定内容]**: [理由]

## 捨てた選択肢と理由

- **[選択肢]**: [不採用の理由]

## ハマりどころ

- **[問題]**: [解決策]

## 学び

- [知見]

## 次にやること

- [ ] [タスク1]
- [ ] [タスク2]

## 関連ファイル

- `path/to/file1` - [役割]
- `path/to/file2` - [役割]
```

### Step 4: 完了報告

生成した `HANDOVER.md` の内容サマリーを表示する。

## ベストプラクティス

- セッション終了前に実行し、作業内容が記憶に新しいうちに記録する
- 「次にやること」は具体的で着手可能な粒度で記述する
- 「捨てた選択肢」は後から同じ議論を繰り返さないために必ず記録する
- HANDOVER.md は `.gitignore` に追加し、リポジトリには含めない
- CLAUDE.md にはプロジェクト全体の不変ルールのみを記載し、HANDOVER.md との役割を分離する

## 注意事項

- HANDOVER.md は毎回上書きされる。過去の内容が必要な場合は事前にバックアップする
- git の作業履歴が少ない場合でも、会話コンテキストから情報を最大限抽出する
- セクション内に記載すべき内容がない場合は「特になし」と記載し、セクション自体は省略しない
