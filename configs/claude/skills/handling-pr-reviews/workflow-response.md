# 返信モード ワークフロー

SKILL.md の Step 1 完了後、以下の手順を実行する。

## Step 2: コミット情報の取得

1. PRメタデータから `baseRefName` を取得（Step 1 で取得済み）
2. ベースブランチからの変更内容を把握:
   ```bash
   git log {baseRefName}..HEAD --oneline
   ```
   ```bash
   git diff {baseRefName}..HEAD
   ```
3. コミット履歴と差分から、どのコメントに対応する修正が行われたかを把握する

## Step 3: コメント分析とトリアージ

コミット差分と各レビューコメントを照合し、以下のカテゴリに分類する:

| カテゴリ | 判断基準 | アクション |
|---------|---------|-----------|
| **A: 修正済み** | コミット差分でコメント指摘箇所が修正されている | 修正内容を説明する返信 |
| **B: 返信のみ** | 意図の誤解、適用不可の提案、設計に関する質問 | 理由説明の返信 |
| **C: 対応不要** | LGTM、情報共有 | 簡潔な返信 or スキップ |

**トリアージ結果をテーブル形式でユーザーに提示し、確認を得てから次のステップへ進む。**

提示フォーマット:

```
| # | ファイル | コメント概要 | カテゴリ | 返信内容 |
|---|---------|------------|---------|---------|
| 1 | src/foo.ts:42 | 変数名を修正すべき | A: 修正済み | 変数名を `userId` に変更しました |
| 2 | src/bar.ts:10 | なぜこの実装にしたか | B: 返信のみ | 設計意図を説明 |
| 3 | src/baz.ts:5 | LGTM | C: 不要 | スキップ |
```

ユーザーがカテゴリ変更や返信内容の修正を指示した場合は反映する。

## Step 4: コメントへの返信投稿

`gh api` でレビューコメントに返信を投稿する。

返信の投稿方法（`allowed-tools` の `Bash(gh api:repos/*/*/pulls/*/comments*)` パターンは POST メソッドも許可する）:
```bash
gh api repos/{owner}/{repo}/pulls/{PR}/comments \
  --method POST \
  -f body="返信内容" \
  -F in_reply_to={parent_comment_id}
```

**注意:** エンドポイントURLを `gh api` の第1引数に置くこと。`--method` 等のフラグはその後に指定する。

返信テンプレート（レビュワーのコメント言語に合わせる）:

- **カテゴリA**: 「修正しました。{変更内容の具体的な説明}」
- **カテゴリB**: 「ご指摘ありがとうございます。{現在のアプローチを維持する理由の説明}」
- **カテゴリC**: 「ご確認ありがとうございます。」（LGTMのみのコメントには返信不要）

**エラー処理:** POST失敗時は該当コメントの失敗を報告し、残りのコメントへの返信は継続する。

## Step 5: サマリー出力

```
## 返信モード 対応サマリー

- 修正済み返信 (カテゴリA): N件
- 返信のみ (カテゴリB): N件
- スキップ (カテゴリC): N件

### 返信済みコメント
- #1: 変数名を userId に変更しました
- #2: 設計意図を説明しました
- #5: 確認の返信を投稿しました

### 失敗した返信
- （なし）
```
