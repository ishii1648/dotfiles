# OpenCode ガイドライン
- ユーザが意見を求めた場合、忖度せず批判的に検討したうえで回答すること

## 人間への確認を最小化
質問・承認要求の前に必ず自己解決を試みること。どうしても必要な場合は作業開始前に `question` ツールでまとめて確認する：
- テストを実行して検証する
- ブラウザや出力で結果を確認する
- ゴールから逆算して次ステップを自己判断する
- 物理的に不可能なもの（SMS認証等）のみ人間に依頼

## ユーザ環境
- シェルは **fish** を使用している。コマンド例を示す際は fish 構文で記述すること（heredoc `<<EOF` は使用不可、代わりに `printf` + `tee` を使う）
- macOS (BSD) 環境。GNU 専用フラグを使わない（例: `cat -A` は無効 → `cat -e` / `cat -v` を使う）

## ツール呼び出しの規律
OpenCode は Claude Code と異なり、Edit/Write/破壊的 Bash と失敗しうる Bash を同一バッチで混ぜても並列キャンセルは起きない。ただし冪等性と着地確認の観点から以下を守る：
- read-only（read/grep/glob/参照系 bash）は並列 OK
- 非0 exit が想定される bash（`pkill` / `grep -c` / `curl` プローブ / `gh ... checks` 等）は末尾に `|| true` を付ける
- ファイル編集・状態確認は `git diff --stat` / `git diff` を唯一の真実として扱う。表示層のメッセージを鵜呑みにしない
- 中断されたアクションを無断で再試行しない（特に push 等の外向き操作）。ユーザが別タスクへ誘導したら、そのタスクを終えてから再開可否を確認する

## 調査結果のまとめ
- 調査結果をまとめる際に表を使う場合は markdown を使うこと
- 調査結果は `.outputs/claude/` に出力すること（global gitignore で除外済み）
- ただし、プロジェクト AGENTS.md で調査ドキュメントの出力先が指定されている場合はそちらに従う

## 実装完了時の自動コミット
コード実装タスクが完了した際は `git commit` まで自動で行う。git remote が設定されている場合は `git push` も自動で行う（PR 作成は不要）。デフォルトブランチに直接コミットしてよい。
